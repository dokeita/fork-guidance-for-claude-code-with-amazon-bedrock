# Issue 006: 管理者 Web UI（クォータダッシュボード）

## 概要

CLI ベースのクォータ管理に加え、Web ブラウザからクォータポリシーの確認・変更・ユーザー使用量の可視化ができる管理者向け Web UI を提供する。

## 背景（Why）

- 現状のクォータ管理は全て `ccwb quota` CLI コマンドで行う必要がある
- 非エンジニアの管理者（IT マネージャー、財務担当）にとって CLI は敷居が高い
- ユーザー一覧の使用量を俯瞰的に確認したい場合、CLI の出力では視認性が低い
- CloudWatch ダッシュボードはメトリクスの可視化に特化しており、ポリシー管理はできない

## 対象（Who / What）

- **影響を受けるユーザー**: クォータ管理を行う IT 管理者、チームリーダー、財務担当
- **対象コンポーネント**: 新規 Web アプリケーション、API Gateway、DynamoDB

## 提供する機能（What）

| 機能 | 説明 |
|------|------|
| ユーザー使用量一覧 | 全ユーザーの月次/日次使用量をテーブル表示、ソート・フィルタ可能 |
| ポリシー管理 | デフォルト/グループ/ユーザーポリシーの CRUD |
| 使用量グラフ | ユーザー別の使用量推移（日次/週次/月次） |
| アラート履歴 | 送信済みアラートの一覧と詳細 |
| ブロック管理 | ブロック中ユーザーの確認と解除 |
| 一括操作 | CSV アップロードによるポリシー一括設定 |

## 解決策の候補（How）

### 案 A: S3 + CloudFront + API Gateway（サーバーレス SPA）

静的フロントエンド（React/Vue）を S3 にホスト、バックエンドは API Gateway + Lambda。

```
CloudFront → S3 (SPA)
                ↓ API コール
           API Gateway (IAM/Cognito 認証) → Lambda → DynamoDB
```

- **メリット**: サーバーレス、低コスト、スケーラブル
- **デメリット**: フロントエンド開発が必要、ビルドパイプライン追加

### 案 B: 既存 ALB に管理画面を追加

モニタリング用 ALB に管理画面のパスを追加し、Lambda で HTML を返す。

- **メリット**: 追加インフラ最小、既存の認証（ALB OIDC）を流用
- **デメリット**: UI の表現力に制限、Central モード必須

### 案 C: CloudWatch ダッシュボードのカスタムウィジェット拡張

CloudWatch ダッシュボードにカスタム HTML ウィジェットを追加。

- **メリット**: 既存ダッシュボードに統合、追加インフラ不要
- **デメリット**: CloudWatch ウィジェットの制約（操作性、レイアウト）

## 実装場所（Where）

## 優先度・時期（When）

- **優先度**: Low
- **前提**: Quota Monitoring の全機能が安定稼働、ユーザーからのフィードバック収集後
- **想定工数**: 10-15日

## 受け入れ条件

- [ ] Web ブラウザからクォータポリシーの閲覧・編集ができる
- [ ] ユーザー使用量の一覧がテーブル形式で表示される
- [ ] 管理者認証が必須（IAM or OIDC）
- [ ] `ccwb deploy dashboard-ui` でデプロイできる
- [ ] モバイルブラウザでも最低限の操作が可能（レスポンシブ）
- [ ] 既存の CLI 操作と完全に互換（同じ DynamoDB テーブルを参照）

## リスク

- フロントエンドフレームワークの選定と保守コスト
- セキュリティ（XSS、CSRF、認証バイパス）の考慮が必要
- CLI との整合性維持（両方から同じデータを操作するため競合の可能性）
